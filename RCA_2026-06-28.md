# Root Cause Analysis (RCA): 2026-06-28 Morning Briefing NameError Incident

**Incident Date:** 2026-06-28  
**Resolution Date:** 2026-06-28  
**Severity:** High (Production Cron Job failed to send morning briefs to all users)  
**Resolution Version:** v3.0.1 (Revision `accountability-agent-00021-df7`)

---

## 🔍 Incident Summary

On the morning of June 28, 2026, users did not receive their scheduled morning briefings. Cloud Run logs indicated that while the Google Cloud Scheduler triggered the `/cron/morning_briefing` endpoint successfully and fetched active timezones, the execution loop crashed for all users with a Python `NameError`:

```
❌ Failed to send briefing to 1034585649: name 'task_list' is not defined
```

---

## 🕵️‍♂️ Root Cause Analysis

### What Happened?
During the implementation of the **Daily Focus Engine (To-Dos)**, the morning brief was updated to display interactive checkbox buttons. To generate this keyboard, `briefing_service.get_briefing_keyboard` was called inside the route function in `src/main.py` with `task_list` passed as an argument.

However, the variable `task_list` was never retrieved or defined within the scope of the `morning_briefing` route handler:
```python
# Faulty code inside src/main.py:morning_briefing:
briefing = await briefing_service.generate_briefing(user)
if briefing is None:
    continue

# ERROR: task_list was not retrieved from task_service here!
keyboard = briefing_service.get_briefing_keyboard(task_list) 
```

### Why Did it Pass Tests & Code Review?
1. **Mocking & Isolation of Unit Tests:** The unit test suite for the briefing service (`tests/test_briefing_service.py`) tested the underlying `BriefingService.generate_briefing` method directly. It did not invoke the FastAPI route handler where the integration with the Telegram bot client and keyboard happens.
2. **Missing Endpoint Integration Coverage:** While `tests/test_fastapi_endpoints.py` tested standard check-in and reminder endpoints, there was **no test case** covering the `/cron/morning_briefing` HTTP route. 
3. **Pre-Deploy Compilation Limitations:** The pre-deploy checks script ran `python3 -m compileall src`, which validates syntax and compiles bytecode but **does not run static analysis (like name resolution checking)**. Undefined variables compile successfully and only raise errors at runtime.

---

## 🛠️ Mitigations & Future Prevention Plan

To prevent similar runtime regression errors, we have implemented the following actions:

### 1. Short-Term Fixes (Completed)
* **Code Fixed**: Resolved name resolution by importing `task_service` and querying the user's daily tasks relative to their timezone's current date before keyboard compilation.
* **Test Added**: Appended `TestMorningBriefingCron` to `tests/test_fastapi_endpoints.py`. This test mocks the database responses and asserts that the `/cron/morning_briefing` endpoint executes end-to-end and successfully dispatches bot messages.

### 2. Long-Term Preventative Gates (Proposed)
* **Add Static Code Analysis (Linting)**: Integrate a linter (like `pylint`, `flake8`, or `mypy`) into `scripts/pre_deploy_check.py` or the CI pipeline. Undefined variable names will immediately fail the build check.
* **Expand Integration Testing**: Enforce that any new HTTP endpoint or Cron route must be accompanied by an ASGI `TestClient` endpoint test to verify execution paths.
